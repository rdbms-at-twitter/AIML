# MeCab 日本語テキスト処理サンプル

MeCab を使った日本語の形態素解析・抽出型要約のサンプルスクリプト集です。Amazon Aurora の説明文を題材に、形態素解析結果の表示、TF（単語頻度）ベースの抽出型要約、そしてその内部処理（トークン化・重みづけ）の可視化を行います。

## 動作環境

- Python 3.x
- [MeCab](https://taku910.github.io/mecab/) + Python バインディング (`mecab-python3` など)

```bash
pip install mecab-python3
# 辞書が別途必要な場合（例: UniDic）
pip install unidic-lite
```

> **辞書による素性フィールドの違いに注意**
> MeCab の辞書によって `node.feature`（カンマ区切りの素性）のフィールド構成が異なります。本スクリプトは、**読みが `feature[6]`、原形が `feature[7]`** に入る辞書構成（UniDic 系）を前提にしています。IPAdic などフィールド構成が異なる辞書では、読み・原形が入れ替わったりずれたりするため、該当インデックスを調整してください。

## ファイル一覧

| ファイル | 用途 |
|---|---|
| `wakachi_mecab.py` | 形態素解析の結果（表層形・品詞・品詞細分類・読み・原形）を罫線テーブルで表示 |
| `youyaku_mecab.py` | TF（単語頻度）ベースの抽出型要約。上位N文を抜き出す |
| `youyaku_verbose.py` | `youyaku_mecab.py` の内部処理（トークン化・重みづけ・スコア計算）を5段階のテーブルで可視化 |

## 1. wakachi_mecab.py — 形態素解析テーブル表示

### 実行している内容

1. `MeCab.Tagger()` で解析器を生成
2. 入力文（デフォルト: `"mecabの分かち書き"`）を `parseToNode()` で1形態素ずつ走査
3. BOS/EOS の空ノードを除外し、各形態素の `feature`（カンマ区切り素性）を分解
   - `feature[0]` = 品詞、`feature[1]` = 品詞細分類、`feature[6]` = 読み、`feature[7]` = 原形
4. 全角文字の表示幅（East Asian Width: 全角=2, 半角=1）を考慮して罫線位置を揃え、テーブル出力

入力文を変えるには、スクリプト末尾の `text = "..."` を書き換えます。

### 実行方法と出力例

```bash
python wakachi_mecab.py
```

```
┌────────────┬──────┬────────────┬────────────┬────────────┐
│ 表層形     │ 品詞 │ 品詞細分類 │ 読み       │ 原形       │
├────────────┼──────┼────────────┼────────────┼────────────┤
│ mecab      │ 名詞 │ 普通名詞   │            │ mecab      │
│ の         │ 助詞 │ 格助詞     │ ノ         │ の         │
│ 分かち書き │ 名詞 │ 普通名詞   │ ワカチガキ │ 分かち書き │
└────────────┴──────┴────────────┴────────────┴────────────┘
```

## 2. youyaku_mecab.py — 抽出型要約

### 実行している内容

1. 題材テキスト（Amazon Aurora の説明文・全10文）を「。」で文に分割し、空文を除外
2. `tokenize()` で各文を形態素解析し、**内容語（名詞・動詞・形容詞）の原形**だけを抽出
3. 全文書での単語出現頻度 `word_frequencies` を集計（これが「重み」）
4. 各文をスコアリング:

   ```
   文のスコア = Σ(文中の各内容語の全体頻度) ÷ 文の語数
   ```

   `÷ 語数`（正規化）で、長い文が有利になりすぎるのを防ぐ
5. スコア上位N文（デフォルト3文）を選び、**元の出現順に戻して**「。」で連結し要約を出力

要約する文数を変えるには `simple_summarize(text, num_sentences=N)` の `N` を変更します。

### 実行方法と出力例

```bash
python youyaku_mecab.py
```

```
Amazon Aurora (Aurora) は完全マネージド型のリレーショナルデータベースエンジンで、MySQL および PostgreSQL と互換性があります。MySQL と PostgreSQL との互換性のあるデータベースエンジンは、その高速分散ストレージを利用するようにカスタマイズされています。また、Aurora はデータベースのクラスター化とレプリケーションを自動化しスタンダード化します。
```

## 3. youyaku_verbose.py — 要約処理の可視化

### 実行している内容

`youyaku_mecab.py` と同じ TF ベース要約を行いつつ、その内部処理を5段階のテーブルで出力します。重みづけの仕組みを理解・デバッグするためのツールです。

出力される5ステップ:

1. **各文のトークン化結果** — 各文がどの内容語に分解されたか、語数とともに表示
2. **単語頻度（重み）上位20** — どの単語が重視されているか（`█` バーグラフ付き）
3. **各文のスコア計算** — 頻度合計・正規化スコア（バーグラフ付き）
4. **選定結果** — スコア上位N文を元の順序に復元して表示
5. **最終要約** — 連結した要約文

### 実行方法と出力例（抜粋）

```bash
python youyaku_verbose.py
```

## 題材テキスト

`youyaku_mecab.py` と `youyaku_verbose.py` は、Amazon Aurora の説明文（全10文）を題材に固定で埋め込んでいます。

## 既知の改善点

現在の要約アルゴリズムは単純な TF（単語頻度）ベースのため、以下の弱点があります（`youyaku_verbose.py` のステップ2で確認できます）:

- 「為る（する）」「居る（いる）」「事（こと）」「有る（ある）」などの機能語が高頻度で上位に来てノイズになる
- 文書全体で頻出するが情報量の少ない語の重みを下げられない

改善の方向性:

- **ストップワード除外** — 機能語をスコアリング対象から弾く（最も効果的で実装が簡単）
- **品詞の絞り込み** — 固有名詞・一般名詞中心にし、補助動詞・非自立語を除外
- **TF-IDF 化** — 文書共通の頻出語の重みを下げる
- **TextRank** — 文間類似度グラフに PageRank を適用して重要文を選ぶ
